# 产品搜索、对比与邮件询盘

## 统一入口

- `/zh/search`、`/en/search` 支持 `keywords`，也兼容 `query`。
- 原 `/{locale}/gas-imaging-assistant?query=...` 永久重定向到统一搜索页，并保留查询内容。
- 页面只有搜索、选产品、对比、询盘，不再包含“描述需求”和“向资料提问”的分步流程。
- 最多选 12 款，跨搜索保留选择。对比表横向滚动、首列 sticky；不显示目录价格，产品详情只链接本站。

## 实际检索实现与边界

`server/src/modules/knowledge/catalog-retriever.js` 使用 PostgreSQL 保存**稀疏特征向量**，不是原来的三款气体相机 AND 筛选，也不是大模型 embedding 或 pgvector ANN：

1. 从全部已发布产品及已发布分类读取当前资料，排除样例、草稿。审核气体事实仅在仍公开且已审核时补充。
2. 型号、名称、规格、分类、公开描述按权重构造词、中文双字片段和中英文部件同义词特征；归一化后写入 `knowledge.product_vectors.embedding`（JSONB）。
3. 型号按完整词匹配，`K10` 不会误当作 `K100`。支持“板子 / 板卡 / board”“目镜 / eyepiece”等别称。
4. 按“或者 / 或 / or / 逗号”等拆分备选需求，在 SQL 中计算各分支与向量的余弦相似度；与关键词命中取并集、去重并按相关度排序。
5. 每次读取当前目录，按内容哈希和 `catalog-sparse-v1` 版本更新变更的向量；召回时回查产品、分类发布状态，不能因为旧向量仍存在就返回下架产品。

该方案不需要外部模型密钥、额外向量服务或本地大模型，适用于当前小规模目录。它是词汇 / 同义词特征向量召回，不具备任意自然语言推理能力；相关候选不代表所有工况、排除条件或参数范围已验证。页面明确提示实际配置和适用性需要工作人员确认。以后接入稠密语义模型时应使用独立模型版本和重建策略，不能将不同类型的向量混用。

向量内容仅来自公开产品资料，不索引姓名、邮箱、询盘正文或确认凭据。迁移 `007_catalog_inquiries.sql` 会随服务启动执行。

## 邮件与输入限制

- 姓名、邮箱：各最多 100 字符。普通联系表单与搜索询盘均执行前端 `maxLength` 和服务端校验。
- 普通联系表单正文：最多 1000 字。
- 搜索询盘手填内容：搜索词 + 补充要求 + 兼容旧客户端的 question 合计最多 1000 字；自动附上的产品名称、参数、本站详情地址不截断。
- 搜索词本身最多 500 字符。限制使用 JavaScript / HTML 一致的 UTF-16 长度，避免前后端不同计数。
- 预览有效期 30 分钟。确认需要明确同意、正确凭据、有效联系方式；发送前回查当前公开产品信息，变化后要求重新预览。
- 使用现有 QQ 优先、Gmail 备用 SMTP。收件人为现有 `CONTACT_RECIPIENT_EMAIL`，客户邮箱作为 Reply-To。
- 发送前建立 `mail_tasks` 记录并将询盘标记为 `sending`；只有 SMTP 接受发送后才返回 `delivery: sent`，页面显示“询盘邮件发送成功，请静待工作人员与您联系”，不展示询盘编号。
- `SELECT ... FOR UPDATE` 串行领取发送任务；发送中不能重复领取，已发送的确认请求幂等返回。SMTP 明确失败时标记 `failed` 并允许在有效期内重试。
- 若进程在 SMTP 发送中断开，或 SMTP 已接受但落库失败，记录保留为 `sending`，不自动重发以避免重复邮件。管理员需先核对 SMTP / 邮件日志，再人工处理状态。SMTP 接受不等同于收件箱最终投递保证。
- 管理端仍可使用内部询盘 ID 跟踪 `delivery_status` 和邮件任务，前台不显示内部 ID。

## 验收

```bash
cd server
npm run test:contact
npm run test:search
npm run verify:knowledge

cd ../next
npx tsc --noEmit --incremental false
npm run lint
npm run build
```

`verify:knowledge` 在当前数据库事务内创建隔离的测试 schema、复制公开目录，模拟 SMTP，检查真实 SQL 的全目录并集召回、语言隔离、下架过滤、对比、字数限制、确认防重发和 HTTP 鉴权。最终回滚整个测试 schema，不修改实际产品或客户询盘，不发送真实邮件。需要当前数据库用户具有创建 schema 的权限。

部署后检查中英文搜索、旧地址重定向、手机页面与横向对比；如需实际验证 SMTP，只发送明确标记为测试的询盘，不使用客户个人信息。

## 成像组件 3D

`gla07512k-t2-itz1212ip-imaging-kit` 在模型就绪后默认循环轮播五个组件，同步切换高亮、编号和说明。每个组件展示 4 秒，完整装配 / 展开 / 组件展示 / 收拢周期为 26 秒；重置视图恢复播放，手动选择或暂停停止轮播。进入视区后运行，离开视区暂停渲染，仍尊重系统“减少动态效果”偏好。页面不再提供“查看原始 STEP 文件”链接。
